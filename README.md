# LearnBoost

PDF를 읽다가 이해가 필요한 문장을 골라 질문하고, 답변의 출처에서 원문으로 돌아갈 수 있는 한국어 학습 공간입니다. 작업 공간, 노트, 일지, 할 일, 캔버스, 기억, 대화 분기 기능을 함께 제공합니다.

## 실행

Node.js 22.13 이상이 필요합니다.

```sh
npm start
```

첫 실행에서 잠금 파일에 맞춰 패키지를 설치하고 화면을 빌드합니다. 홈페이지는 http://127.0.0.1:3000, 작업 공간은 http://127.0.0.1:3000/app 입니다. 개발 중에는 `npm run dev`, 자동 테스트에는 `npm test`를 사용합니다.

## PDF에서 질문하기

1. **문서**에서 PDF를 올려요. 원본은 이 기기에 저장되고, 추출한 텍스트를 자동으로 나누어 Furiosa로 검색을 준비합니다. 목록에 **검색 가능**이 표시되면 대화에 첨부할 수 있습니다.
2. PDF를 열고 보고 있는 문장을 선택해 **이 부분 질문하기**를 눌러요. 선택한 구절과 페이지가 질문에 붙습니다.
3. 답변의 번호나 출처를 누르면 해당 페이지의 근거 구절이 표시됩니다. 뷰어의 출처 목록으로도 이동할 수 있고, 가운데 구분선을 드래그하거나 방향키로 옮겨 PDF와 대화의 너비를 조절할 수 있습니다.
4. 답변에서 궁금한 문장을 선택해 **대화 이어가기**를 누르면 옆 대화에서 이어갈 수 있습니다.
5. 복습할 구절은 답변 출처 옆의 **필기**로 직접 저장하세요. 뷰어에서 필기를 접거나 펼치고 메모를 편집할 수 있습니다. 전체 답변은 **대화에서 보기**로 엽니다.

표나 그림을 드래그해 범위를 지정하면 Qwen3-VL로 질문할 수 있습니다. 뷰어에서 필기가 붙은 PDF를 별도로 내려받을 수 있습니다.

입력창의 **문서 내용으로만 답하기**를 켜면 첨부 문서와 선택한 구절을 근거로만 답합니다. **문서 검색만 하기**는 관련 구절을 바로 찾을 때 사용합니다. 텍스트가 포함된 50 MB 이하 PDF를 지원합니다. TXT와 Markdown도 업로드해 검색할 수 있습니다.

## Furiosa

`.env.example`을 `.env`로 복사해 서버의 `LLM_API_KEY`에 키를 입력합니다. 설정 변경 후 서버를 다시 시작하세요. 로컬 `.env`는 Git에 포함되지 않습니다.

답변 기본 모델은 `furiosa-ai/gpt-oss-120b`입니다. 입력창에서 GPT-OSS, Gemma 4, EXAONE 4.5, Qwen3-VL, Qwen3-30B 중 선택할 수 있습니다. 검색은 Qwen3-Embedding-8B 임베딩과 BM25 후보 검색을 결합한 뒤 Qwen3-Reranker-8B로 순서를 정합니다. 이전에 생성한 임베딩은 현재 설정과 맞지 않으면 검색 준비를 다시 실행해야 합니다.

**설정 → 연결 확인**에서 확인할 수 있습니다. 답변은 스트리밍으로 표시하고, 접어서 볼 수 있는 진행 단계는 검색과 답변 준비 상태를 보여 줍니다.

파일을 올리면 검색에 사용할 텍스트를 Furiosa에 전송합니다. 검색 준비에 실패하면 문서 목록에서 다시 시도할 수 있습니다. 질문할 때 질문, 대화 문맥, 답변에 쓰이는 발췌문을 전송합니다. 영역 질문에는 지정한 영역의 이미지도 포함됩니다. 원본 파일과 검색 인덱스는 로컬 `data/`에, 대화와 작업 공간 데이터는 브라우저에 저장합니다. 설정에서 작업 공간을 JSON으로 내려받을 수 있습니다.

## 캔버스와 학습 PDF

캔버스를 우클릭하거나 상단 버튼을 사용해 노트를 새로 만들고 배치할 수 있습니다. 기존 노트를 고를 때는 아직 배치하지 않은 노트가 먼저 보이며, 같은 노트를 여러 번 놓을 수 있습니다. **학습 PDF**를 열면 개념도, 개념별 이해도와 노트가 한 문서로 정리됩니다. 미리보기의 인쇄 창에서 **PDF로 저장**을 선택하세요.

## 개념 정리

사이드바의 **개념 정리**에서 개념을 추가하고 이름, 분류, 5단계 이해도, 개념 노트를 편집할 수 있습니다. 답변에서 구절을 선택한 뒤 **개념 추가**를 눌러도 됩니다. 같은 작업 공간의 모든 대화는 개념별 이해도를 참고하고, 답변 안의 보충 설명을 펼쳐 읽을 수 있습니다.

답변 후 관련 개념과 이해도에 대한 의견을 받기 위해 질문, 답변 일부, 작업 공간 개념 이름과 이해도를 Furiosa에 보냅니다. AI가 이해도를 변경하면 알림의 **이해도 수정**으로 해당 개념을 열 수 있습니다. **AI 이해도 변경 잠금**을 켜면 그 개념의 평가를 직접 관리할 수 있습니다.

## 기획안과 한국어 RAG 평가

`26-2_실전SW프로젝트_8팀_기획안.pdf` 17–27쪽의 문서 질의, 원문 선택, 페이지 근거, 문서 한정 모드와 정량 평가 기준을 반영했습니다. Furiosa 가이드 원본은 현재 폴더에 없어 기존 설정의 엔드포인트와 실제 API 응답을 기준으로 연결했습니다.

평가에 사용한 공개 한국어 RAG 데이터와 PDF는 로컬 `data/benchmark/`에 저장합니다. 질문과 정답은 Allganize 공개본, PDF는 원본 페이지를 보관한 공개 재구성본에서 받습니다. [Allganize 데이터](https://huggingface.co/datasets/allganize/RAG-Evaluation-Dataset-KO), [PDF 배포본](https://huggingface.co/datasets/datalama/RAG-Evaluation-Dataset-KO).

```sh
node scripts/prepare-rag-eval.mjs
node scripts/eval-rag.mjs --rounds 3 --concurrency 12
```

평가는 근거 페이지 라벨과 추출 가능한 텍스트가 있는 공개 문단형 140문항 중 128문항을 질문 해시 순으로 골라 반복합니다. 기획안의 팀 평가 문항 목록은 현재 폴더에 없습니다. 문서 한정 RAG, 검색을 끈 대화, 다른 문서를 첨부한 대화에 같은 질문을 보냅니다. 결과 JSON과 문항별 JSONL은 `data/benchmark/results/`에 기록됩니다.
